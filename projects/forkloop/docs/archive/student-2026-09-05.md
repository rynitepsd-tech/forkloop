**Reading the histogram before the rate.** This is not a 0 % on the task; it is a 0 % on the action format. The
base model was trained for a browser harness with `visit_url`, and it reaches for it the moment the task says
"OpenEMR at http://localhost/openemr": 10 rejected `visit_url` calls end 24 of the 30 episodes at the env's
invalid-action limit, typically inside 30 steps, before any of them has logged into OpenEMR. Between the rejections
the actions are sane and on-task (click the omnibox, `ctrl+l`, `alt+d`, the OpenEMR login fields at the right
coordinates, `admin` typed into the username field) — the model simply never types a URL by hand. The other six
episodes stopped themselves with Fara's critical-point behaviour (`ask_user_question` → `done(success=false)`), five
of them within 20 steps. Zero wrong-record, zero collateral edits, zero transcription/decoy errors: nothing got far
enough to make those mistakes. Gate 1 fires (invalid rate ≫ 5 %), so the parser was fixed and the same 30 seeds
re-run once (step 3b).

**The fix** (`forkloop/policies/student.py`, `--nav-macro`, commit 2fa1a77, 204 offline tests): the policy
expands `visit_url` into the contract's own navigation, click(640, 90) → key(ctrl+a) → type(url) → key(Return),
over four env steps with one model call (the queued three are marked `macro` in the step meta), and `history_back`
into key(alt+Left); the tool schema advertises both. This is exactly the sequence the teacher prompts spell out and
the scripted GUI fixture uses; the contract action space is unchanged.

  need the admin password"`, which the parser maps to `done(success=false)`.
- 19/30 spend the whole 120-step budget cycling login page → `/openemr` → login page; 3 of those are strict loops

## The SFT ladder plan (for a rented GPU; nothing here was run)

The base number is a floor set by two behaviours the SFT data corrects directly (the two-field login is in every
verified family-3 trajectory; navigation is compact actions, never `visit_url`). The rungs are the brief's
25 / 50 / 94 family-3 episodes, drawn in `task_id` order so the subsets nest, from the two v5 runs (77 + 38 = 115
verified episodes, 7,609 records). SFT records reference screenshots by absolute path under `runs/`, so the two run
directories (≈ 1.9 GB of PNGs) go to the GPU box with the repo:

```bash
# on this Mac: ship the repo and the two runs (runs/ is git-ignored)
rsync -a --exclude venv --exclude venv-mlx ~/Desktop/Solari/repo/projects/forkloop/  gpu:~/forkloop/
rsync -a runs/luna-v5-f3-s20-99 runs/luna-v5-f3-s100-139  gpu:~/forkloop/runs/

# on the GPU box (one 80 GB card; python3.11, pip install -e ".[train]")
cd ~/forkloop && export PYTHONPATH=.
for N in 25 50 94; do
  python -m train.make_sft --run-dir runs/luna-v5-f3-s20-99 --run-dir runs/luna-v5-f3-s100-139 \
    --families resolve_denial --exclude-split 'heldout_*' --history-k 8 --limit $N --out data/sft_f3_$N.jsonl
done
python -m train.make_sft --run-dir runs/luna-v5-f3-s20-99 --run-dir runs/luna-v5-f3-s100-139 \
  --families resolve_denial --exclude-split 'heldout_*' --history-k 8 --out data/sft_f3_all.jsonl   # 115 episodes

for N in 25 50 94 all; do
  python -m train.train_lora --model microsoft/Fara1.5-4B --data data/sft_f3_$N.jsonl \
    --output-dir ckpt/fara_f3_$N --prompt-style fara --history-k 8 --max-image-side 1280 --coord-space norm1000 \
    --epochs 2 --lr 1e-4 --lora-r 16 --lora-alpha 32 --lora-dropout 0.05 --batch-size 1 --grad-accum 8 \
    --dtype bf16 --save-steps 200 --merge-out ckpt/fara_f3_$N/merged
  vllm serve ckpt/fara_f3_$N/merged --port 8011 --served-model-name fara-f3-$N --dtype bfloat16 --max-model-len 16384
done
```
