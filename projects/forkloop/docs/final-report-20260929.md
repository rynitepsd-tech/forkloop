## 2. The learning experiment (exp1)

Question: does a Qwen3.8-27B student trained on Forkloop corrections of its own failures (A2) do
better on 150 held-out tasks than the untrained student (A0), than one trained on teacher
demonstrations from initial states (A1) at matched collection cost, and than one trained on
full-restart repairs (A3)? Three LoRA training runs per trained arm, one attempt per cell, SQL
verifier, family-balanced success, paired bootstrap.

**Evaluation results** (`docs/results-exp1.md`; all 1,650 planned cells scored, none unscored;
student alone, one attempt per task, family-balanced success on the 150 registered final-test tasks):

| Model | Success | Per family (compose / reschedule / denial / insurance) |
| --- | ---: | --- |
| A0 untrained | 0.033 | 0.00 / 0.00 / 0.00 / 0.13 |
| S_W warm start (W only) | 0.208 | 0.07 / 0.00 / 0.30 / 0.47 |
| A1 demonstrations (3 runs) | 0.268 | 0.11 / 0.00 / 0.43 / 0.53 |
| A2 Forkloop corrections (3 runs) | 0.260 | 0.12 / 0.00 / 0.40 / 0.52 |
| A3 full-restart repairs (3 runs) | 0.269 | 0.10 / 0.00 / 0.38 / 0.60 |

| Paired comparison | Difference | 95% CI | Sign test |
| --- | ---: | --- | ---: |
| A2 − A0 | +0.226 | [+0.165, +0.290] | 35 vs 0 tasks, p = 6e-11 |
| A2 − A1 | −0.008 | [−0.042, +0.022] | 4 vs 6, p = 0.75 |
| A2 − A3 | −0.010 | [−0.064, +0.054] | 8 vs 8, p = 1 |
| S_W − A0 | +0.175 | [+0.117, +0.237] | 23 vs 0, p = 2e-7 |

**What this means.**
- **The registered hypothesis is not supported.** Training on Forkloop corrections did not beat
  training on teacher demonstrations of the same (counted) collection cost, nor full-restart repairs.
  The registered "practically meaningful effect" needed A2 − A1 > 0 with the interval excluding 0 (or
  the untested half-cost alternative); A2 − A1 is −0.008 [−0.042, +0.022].
- Every trained arm improved the student a lot over A0 (+0.23), but most of that came from the shared
  warm-start data W (S_W − A0 = +0.175); each arm's own data added about +0.05–0.06 over S_W, and the
  three arms were indistinguishable. Rescheduling stayed at 0 for every model (no rescheduling data).
- At matched cost the arms' own data differed greatly in size (78 vs 21 vs 24 verified paths), yet
  gave the same result: with ~29% of training examples, A2's 21 corrections did as well as A1's 78
  demonstrations at ~63%. This is suggestive of higher value per example for corrections, but it rests
  on one small dataset per arm and was not a registered test.
- Robustness: identical under "unscored = failure" and "key-name failures = policy failures" (no cell
  was unscored). A3's seed 3 (the only run on the H100 dev box) scored 0.208 against 0.296/0.304 for
  seeds 1–2; without it A3 is 0.300 and A2 − A3 = −0.040 [−0.079, −0.004]. Per training run: A1 0.254–
  0.287, A2 0.254–0.263. Main's shard scored lower than aux's for every trained arm (e.g. A1 0.22 vs
  0.32; same split for every model, so comparisons are balanced); the episode time limit ended 1 of
  1,650 evaluation episodes. A0/S_W's aux cells ran earlier on a collection-phase server (median model
  latency 11–12 s vs 16 s) — the only arm-specific server difference.

**Collection (training pool only; measured).**

- Teacher (gpt-5.6-luna) from initial states: warm start W (scored cells) insurance 18/20, denial 15/20, compose 9/18,
  rescheduling 0/19 scored; demonstrations (A1 pool, 160 tasks) insurance 31/40, denial 34/40, compose
  13/40, rescheduling 0/40. **No arm, and not W, contains any verified rescheduling path.**
- Round 1 (S_W, the warm-started student, 160 training tasks): 39 OK — denial 29/40, insurance 6/40,
  compose 4/40, rescheduling 0/40 → 121 failures repaired in both modes.
- Repairs (counted = first repair with no unscored branch): checkpoint mode 47 counted of 382 repairs
  run; full restart 80 counted of 328. Most of the rest were voided by infrastructure (§3).
- **Matched collection cost** (B = $27.27, the demonstration arm's total, charging counted work
  only; rates $0.35 per world-hour, $0.001 per student step):

  | Arm | Units | Verified paths | Tasks | Records |
  | --- | ---: | ---: | ---: | ---: |
  | A1 demonstrations | 160 | 78 | 78 | 4,167 |
  | A2 Forkloop corrections | 17 | 21 | 10 | 1,014 (24% are step-0 restarts) |
  | A3 full-restart repairs | 25 | 24 | 9 | 1,197 |

  Each training run saw 800 examples from W ∪ its arm's data, so the arm-specific share was ≈ 63%
  (A1), 29% (A2), 33% (A3).
- **All work, including voided work** (review 2, B1): A1 $29.53, **A2 $374.63**, **A3 $270.58**. Under an
  all-work accounting (B = $29.53) A2 would have had 11 verified paths from 5 tasks and A3 15 from 6,
  against 78 from 78 for A1. Correction data were an order of magnitude more expensive per verified
  path than demonstrations in this setup.
- **Checkpoint vs full-restart repair (exploratory, same failures and teacher):** over the first 50
  failures in selection order, counting only branches from the evidence-chosen restart point (3 tries
  per mode), 5 failures were repaired only from the checkpoint and 3 only from the start (sign test
  p = 0.73). The earlier "7 vs 1" counted the checkpoint mode's step-0 fallback, which gives it up to 6
  tries against 3. No like-for-like advantage of restarting from a checkpoint was shown.
- Restores: replay restores passed the fidelity check in 53% of 1,608 tries (tables equal in 92%;
  p50 61 s, p90 403 s); full-restart resets passed 85% of 1,120. Replay checkpoint capture took
  ≈ 26 s (p50) per checkpoint during the student's attempt.

## 3. What worked, what did not

**Worked (measured).**
- The loop on real software, end to end, with evidence: Solari flagship (6/6 student failures; 4
  repaired, 2 from step-8 VM snapshots with 79 s restores, all checksummed tables equal, screen
  distance 0; dataset `ds-fc98852a715d`, 425 records; all 30 checkpoint snapshots deleted);
  Kanboard (13 student failures in three configurations, 5 repaired in the third; 29/29 restores
  with equal tables; `ds-a504e6fca3fb`, 136 records; OpenAI $0.63); exp1's featured repair
  (`docs/evidence/exp1/`: the student stored `AUTH-35K98047` where the letter said `AUTH-35K90047`;
  from the step-12 "origin" checkpoint, 2 of 3 restored copies verified).
- Registered protocol, dated deviations, two independent reviews, no final-test outcome read before
  every cell ran; datasets immutable with lineage; accounting recoverable after interruptions.

**Did not work, or not fully.**
- **Teacher capability:** the registered teacher cannot solve rescheduling from the initial state.
- **OpenAI credit ran out** at ≈ 14:05 UTC on Sep 29 (HTTP 429 `insufficient_quota`); for six hours
  every teacher call was refused. It was first misdiagnosed as a rate limit from the status line alone
  (protocol 15:28, corrected 20:10). Credit was restored ≈ 20:10.
- **Dropped hosted connections** (`ReadError`) voided about a third of branches for a while; hosted
  requests are now re-sent with per-send reservations (`229eaf9`).
- **`ctrl+-` key-name bug:** the Docker backend cannot send `ctrl+-`; the policy triggers it, so it is
  not random infrastructure (review 2, M2). Left unfixed until exp1 ends so every arm runs the same
  backend.
- **Replay restores** are not reliably deterministic (53% pass); failed restores are retried, then
  unscored. The docs no longer call replay "deterministic".
- **Checkpoint branches inherit the student's elapsed time** (`restore.py`), so deep restarts had
  little wall time left: branches from restart steps 30–69 ended on the time limit 19 of 26 times, 70+
  25 of 27 (full restarts: 114 of 321). This disadvantaged the Forkloop arm (review 2, M5).
- **Accounting changed after the first datasets were seen** (protocol 15:28): void work is charged to
  no arm, including failed replay restores, a cost of the checkpoint method; the voiding rule also
  selects on outcome (failing branches run longer and checkpoint repairs run more branches; review 2,
  B1, M1). All-work numbers are reported beside the counted ones.
- **Small datasets:** one collected dataset per arm (A2: 21 paths from 10 tasks); trained-arm
  intervals are conditional on it (review 2, M4). The registered "half its collection cost" criterion
  was not tested (no B/4 or B/2 models were trained).
- **Operator errors:** killing the phase chain's tmux session interrupted 37 round-1 attempts; two
  early starts of main's A0/S_W shard were stopped (server load; Docker world cap) — those attempts
  are annotated and not counted as tries (protocol 2026-09-30 12:30); an evaluation under pre-review
  scoring (`exp1-final`) was voided unread; the first matched-cost datasets and 9 training runs on
  them are void (never evaluated).
- **A3 seed 3** trained on the H100 dev box (same software versions, data and configuration as seeds
  1–2; its first-step loss 1.05 vs 1.50–1.72 elsewhere); results are shown with and without it.
- **Not done by this session (permission checks):** pushing branch `correction-engine-20260929`,
  reading `~/.forkloop/reap.log`, `launchctl print`, and redirecting a log to steer orchestration.
